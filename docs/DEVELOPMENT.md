# 传统农场开发文档

## 1. 当前基线

`origin/stage1` 已合入 `main`，提交 `ff21ee8` 提供第一版可玩循环：两种作物、消耗型种子、每日浇水、睡眠、有限背包、固定收购点、种子商店、金币和 JSON 存档。

当前实现仍是单窗口原型，后续工作应围绕日制农场体验打磨，不能再按旧的增量自动化计划扩张范围。

## 2. 开发顺序

### S1：基础闭环（已完成第一版）

- 保留现有地图、角色、碰撞和工具栏。
- 用 `CropCatalog` 描述作物生长天数、产量、售价和种子价格。
- 用 `GameClock` 统一时间和睡眠跨天。
- 用 `WorldState` 保存土地、浇水和作物状态。
- 用 `Inventory`、`EconomyService` 和 `SaveManager` 管理资产。

### S2：体验清晰化（当前执行阶段）

1. 在 HUD 中稳定显示日期、时间、金币、背包容量、两种种子和作物数量。
2. 补充第一次锄地、播种、浇水、睡眠、收获、出售的操作提示。
3. 为小麦和土豆接入可区分的播种/成长/成熟贴图，缺图时保留可读占位反馈。
4. 统一成功、失败和日结算消息，避免操作结果只写入日志。
5. 补充背包、出售和存档的边界测试。

### S3：小规模内容扩展

- 增加一到两种作物，验证短周期、长周期和高产量的差异。
- 增加有限的可购买地块，扩地只改变可用耕地集合。
- 增加分类出售和购买数量选择。
- 增加一到两项农具便利升级，例如浇水范围或背包容量；不引入自动生产。

### S4：发布打磨

- 根据试玩数据调整种子价格、售价、生长天数和初始资源。
- 完成中文字体、窗口缩放、音效和新手流程检查。
- 用 Qt Release 构建和核心测试生成可运行发布包。

## 3. 状态与规则

- 只有 `GameClock` 能推进日期；自然跨日和睡眠调用同一日结算逻辑。
- 每块土地记录耕地、当日浇水、作物类型和有效生长日。
- 只有空耕地能播种；播种成功才扣除一颗种子。
- 只有成熟作物能收获；整格产量无法装入背包时整格失败。
- 出售只处理玩家背包，且必须通过收购点距离校验。
- 商店购买先校验金币，失败不扣金币、不增加种子。
- 存档保存完整游戏状态，并在原子写入失败时保留旧档。

## 4. 模块职责

| 模块 | 责任 |
| --- | --- |
| `WorldState` / `GameClock` | 土地、作物、浇水和日期结算 |
| `CropCatalog` | 作物静态配置 |
| `Inventory` / `EconomyService` | 背包容量、种子、金币、出售和购买 |
| `SaveManager` | 版本化 JSON 存档和备份 |
| `MapWidget` / `MapRenderer` | 输入、镜头和状态绘制 |
| `MainWindow` / `SeedShopDialog` | 组装界面、提示和商店交互 |

界面不得保存第二份金币、种子或作物数量，也不得在绘制或动画回调中发放收益。

## 6. 验证命令

在 Qt 6.10.3 / MinGW 环境中：

```powershell
qmake CHECK.pro CONFIG+=release
mingw32-make -j2
qmake tests/tests.pro CONFIG+=release
mingw32-make -j2
core_tests.exe -txt
```

测试必须记录实际 Kit、提交号和结果；不能把历史编译记录当作当前验证。
