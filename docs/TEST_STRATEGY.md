# 传统农场测试策略

## 当前基线

本轮使用 Qt 6.10.3 / MinGW 13.1 重新构建 `main`。应用 Release 构建成功，`tests/tests.pro` 构建成功；核心测试程序在补齐 Qt 运行库路径后退出码为 0。

## 自动测试重点

| 区域 | 当前覆盖或下一步 |
| --- | --- |
| 时间 | 游戏分钟、日历换算、睡眠到次日早晨 |
| 地图 | 地图尺寸、图层分类、碰撞和有效地块 |
| 农田 | 锄地、播种消耗、浇水、按有效浇水日成长、空耕地恢复 |
| 收获 | 成熟判定、产量、背包不足时整格保留、重复收获安全 |
| 经济 | 到站出售、金币结算、种子购买、金币不足不变 |
| 存档 | JSON 往返、备份恢复、坏档不覆盖有效进度 |

## S2 新增测试

1. 小麦 3 个有效浇水日成熟，土豆 5 个有效浇水日成熟。
2. 中间漏浇时只停滞一天，不死亡、不倒退。
3. 土豆产量无法全部放入背包时，背包和田地都保持原状态。
4. 远离收购点出售失败，靠近收购点只结算一次。
5. 种子购买金币不足时金币和种子数量均不变化。
6. 睡眠和自然跨日不能重复推进同一天。

## 人工验收

- 从新局完成锄地、播种、浇水、睡眠、收获、出售和买种子。
- 观察浇水后的湿润地块与次日恢复效果。
- 分别验证背包满、无种子、金币不足和远离交互区的提示。
- 关闭并重启后核对日期、金币、种子、背包和农田。
- 调整窗口大小，确认画布居中、HUD 不遮挡关键交互。

## 验证命令

```powershell
qmake CHECK.pro CONFIG+=release
mingw32-make -j2
qmake tests/tests.pro CONFIG+=release
mingw32-make -j2
core_tests.exe -txt
```

命令中的 `qmake`、`mingw32-make` 和运行时 DLL 必须来自同一个 Qt Kit。未执行 GUI 人工流程时，不得在报告中写成已通过。
