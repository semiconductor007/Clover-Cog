# 传统农场执行计划

本计划取代旧的“增量自动化”任务表。目标是先把日制种植做成稳定、容易理解的小型游戏，再决定是否加入更复杂的生活模拟内容。

## 当前执行批次（2026-11-02）

本轮执行地图扩建、新增作物、自然昼夜循环与家的场景交互，使用现有资源扩大 `map6.tmj`，新区开局即可进入。在小麦、土豆基础上增加 1–2 种作物，总计 3–4 种。本轮使用新局验证，付费解锁和旧存档迁移不列入交付。

| 任务 | 负责人 | 执行与交接 |
| --- | --- | --- |
| MAP-001 地图制图 | A | 先确定尺寸和布局，收集 B/C/D 的图层与坐标需求，加入可进入的小屋、门口与床铺布局，统一保存地图和资源表 |
| MAP-002 农田与新增作物 | B | 独立确认品种，交 E 准备素材，和 D 对齐数值及施肥规则，先交付作物目录与规则，再接入新田，和 D 对齐自然/睡眠跨日日结算，验证全部作物种植循环 |
| MAP-003 通行与种植输入/显示 | C | 检查桥、道路、障碍和边界，交 A 修订碰撞图层，接入新种子选择、播种和成长显示，处理家门通行与 E 的昼夜绘制方案 |
| MAP-004 时间/睡眠与作物交易 | D | 先交付连续时间与日结算调度，接入家中睡眠、功能区、新作物交易及基础肥料的购买/库存/扣除，完成后将主窗口交 E |
| MAP-005 昼夜表现/界面与素材 | E | 先提供昼夜亮度/色调方案给 C，按 B 确定的品种准备阶段图和肥料图标，准备中文名称/图标，和 C 对齐工具栏，接到主窗口后展示全部作物数量并完善操作反馈 |

每人承担开发与自测，全组共同验证包含每种新增作物购买、选择播种、成长、收获、出售及新档重开的完整流程，以及肥料购买/施用/失败不扣/新档恢复、整夜不睡、午夜前睡、凌晨睡、重复按键不重复结算，核对家的通行和夜间可读性，并分别记录 Mac/Windows 构建和运行结果。任务状态与完成条件以 [DEVELOPMENT.md 第 0 节](DEVELOPMENT.md#0-本轮任务分配2026-11-02) 为唯一登记入口，文件归属见 [FILE_OWNERSHIP.md](FILE_OWNERSHIP.md)。成员姓名、账号和分支统一在 TEAM_MODULES.md 的成员认领表填写，任务均待认领。

以下 S1–S4 为阶段路线参考，具体工作状态统一以开发文档的完整待办为准。

## 完整工作与执行顺序

具体工作及当前实现状态统一见 [DEVELOPMENT.md 完整待办](DEVELOPMENT.md#完整待办与当前实现盘点)。五个 MAP 编号是任务包，覆盖地图与家、农田/作物、操作/镜头、时间/交易、界面/反馈，并包含各自的规则测试及试玩。

1. A 确定地图和家的布局；B 独立确认品种，E 准备素材；D/B 确定连续时间、睡眠和日结算接口。
2. 完成扩图、新作物全流程、昼夜与家的交互，逐一接通工具栏、商店、背包、HUD 和保存恢复。
3. 完善旧/新作物独立阶段图、中文字体、操作结果与失败提示、初始窗口/缩放、UI 焦点及音频，回归全部作物和时钟边界。
4. 全组试玩数值，修复缺陷，记录 Mac/Windows 结果；A 汇总素材说明和 Release 发布包，各平台在无 Qt 开发环境的对应机器验证。
5. D 牵头完成一种基础肥料购买，B 实现固定施肥效果，C/E 接入操作与显示。分类出售和购买自选数量保留为后续待办；背包扩容和农具多级升级暂不作为必做项。

旧 FARM 编号在不同文档中曾有同号不同任务，开工按开发文档的任务名称和 MAP 编号认领。

## 不在当前计划

自动播种、自动收割、运输、离线收益、订单物流、NPC 社交、四季天气和复杂加工系统不进入 S1–S4。新增范围必须先更新本计划和验收场景。

## 阶段门

- **S1 门**：能完成“种下两种作物—浇水—睡眠—收获—出售—买种子”，并能重启恢复。
- **S2 门**：第一次游玩无需查看源码即可完成上述循环，关键汉字和数字清晰可读。
- **S3 门**：新内容通过配置扩展，本轮新存档可恢复，扩图后新区域可用且出售没有重复结算。
- **S4 门**：Release 发布包在没有 Qt 开发环境的机器上启动，核心测试和人工流程均通过。
