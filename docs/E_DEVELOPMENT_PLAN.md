# E 时间与昼夜开发计划

> 最新规则：06:00—次日02:00前可主动休息，02:00仍未休息则自动昏迷并于床区醒来；新游戏从06:00开始。午夜日切不变，00:00—01:59睡到当天06:00。此前“全天可睡”被用户最新要求覆盖；实现与验证见 [昏迷阶段验收](E_PASSOUT_STAGE_ACCEPTANCE.md)。

## 1 职责与实施基线

本轮 E 是“时间与昼夜”，不是旧 TEAM_MODULES 中的“自动化与物流”。本计划是新版分工的实施提案，不自动改写仓库旧文件所有权。开始编码前，由全组统一认领表和共享文件编辑窗口。

当前本地分支为 stage1，已有背包面板、窗口适配和 Premium UI 素材等未提交工作。正式开始团队开发前，应先审查这些工作，确定是否纳入公共基线，并记录实际提交 SHA。不能让不同成员基于不同未提交版本集成。

## 3 先冻结的规则和接口

### 3.1 已确认规则

- 一天1440游戏分钟；午夜为日切边界。
- 自然流逝和睡眠使用同一套日结算调度。
- 已种作物跨季继续成长，不枯萎。
- 背包打开时游戏时间继续，地图操作被屏蔽。
- 季节从累计日期推导，不独立累计另一套季节状态。
- 主动休息窗口为06:00至次日02:00前；午夜后01:59以前到当天06:00，02:00强制昏迷并回床。目标时间仍严格晚于当前。
- 一段结束日期最多结算一次；跳时不能跳过中间日期。

## 4 时间与日结算设计

### 4.1 累计分钟作为唯一时间源

保留 GameClock。计时从单调经过时间推导，不以 QTimer 回调次数乘以固定值累加。QTimer 只触发检查和重绘；回调延迟不应让游戏时钟变慢。

内部 absoluteDay = gameMinutes / 1440，minuteOfDay = gameMinutes % 1440。显示年、季节和日期交给 B 的统一换算；E 不复制季节公式。

### 4.2 结算标记语义

现有 MainWindow::m_lastProcessedDay 表示已处理进入的日期，WorldState::lastCompletedDay 表示最后完成结算的结束日期。在正常完整状态中，后者等于前者减1；新档第0天对应 -1。

可沿用现有字段，但必须保留注释与一致性校验。若改名或结构，先与 B/D 确认；不能由三方分别新增不同含义的“最后结算日”。

### 4.3 推进顺序

1. 读取目标时间与当前结算标记，列出所有尚未结算的结束日期。
2. 按日期升序调用 B 的日结算：成长、湿润重置、空地恢复及肥料规则由 B 处理。
3. 每一日成功后更新对应标记；失败时保留可恢复的一致状态，停止后续推进并反馈错误。
4. 全部成功后取得新日历快照，刷新 HUD 和季节环境。
5. 向 D 提供一致的保存状态，关键睡眠完成后请求保存。

睡眠期间要阻止新的地图命令插入结算过程。不要在半结算状态中弹模态框或主动 processEvents。当前 worldChanged 可能触发保存，应与 D 检查是否会在农田和主窗口标记尚未对齐时取快照；必要时结算期间合并保存请求，完成后只保存一致状态。

自然时间只前进20分钟但没有跨午夜时，不调用日结算。一次检查跨过多天时逐日执行；第一天清除浇水后，后续日期不能重复沿用旧湿润状态。

## 5 睡眠实现规范

先将自然时间同步至当前时刻并处理未结算日，再检查床边位置和可睡条件。拒绝操作不改时间、不推进成长、不触发成功音效。

| 当前时刻 | 目标 | 新跨过的午夜数 |
| --- | --- | ---: |
| 19:59 | 次日06:00 | 1 |
| 20:00 | 次日06:00 | 1 |
| 22:00 | 次日06:00 | 1 |
| 23:59 | 次日06:00 | 1 |
| 00:00 | 当日06:00 | 0 |
| 02:00 | 自动昏迷，到当日06:00并回床 | 0 |
| 05:59 | 逾期旧档自动恢复到当日06:00 | 0 |
| 06:00 | 次日06:00 | 1 |

成功后立即刷新日期、色调、HUD，显示实际成长/停滞统计并保存。凌晨睡眠的成长统计可能为0，这是正确行为；避免误提示“睡一觉必定成长”。

按键自动重复由C/E共同屏蔽。进行中的重入请求拒绝；醒来后可重新发起并确认下一次睡眠，不能把同一按键的重复触发当作新请求。未来多场景位置判定还需核对场景ID，当前仅有单地图床区。

## 6 昼夜与季节环境

### 6.1 绘制层级

地图、地块、作物、房屋、人物 → 昼夜环境层 → HUD、工具栏、提示、背包、商店。

环境层使用不拦截鼠标的控件或统一世界绘制入口。人物目前是地图子控件，仅在地图 paintEvent 最后填色未必能覆盖人物。与 C 统一层次后再接入，不能在多个地方叠加不同夜幕。

### 6.2 色调计算

- 用时分直接计算颜色和透明度，支持白天、黄昏、夜晚、清晨平滑过渡。
- 环境刷新不能触发任何作物成长或金币变化。
- 读档、跳时、室内外切换后直接计算正确色调。
- 夜间保持可辨认亮度；HUD与面板不受夜幕压暗。
- 室外季节基础色与昼夜色统一合成，避免两层滤镜叠加过暗。
- 首先通过可调整参数实现，再经实际截图和试玩确定颜色；不把试验配色写成最终规则。

### 6.3 季节素材与回退

B 给季节ID，A 给素材路径，E 负责切换和刷新。缺少某季完整地图时保留当前可运行资源并登记缺口，不能把临时滤色称作完整四季地图。冬季积雪、天气和动态雨雪效果不属于本轮必做项。

## 7 日期 HUD 中文与音效

- 日期建议为“第1年 春季 第1天”，时间采用24小时制 HH:mm。
- 用真实中文字符测试字体，不因 Premium UI 包带 TTF 就假定其支持汉字。
- A 统一接入字体和许可说明；E 配置日期、睡眠、无法交互等自己负责的中文反馈。
- HUD 与环境层使用520×320逻辑画布，跟随已有缩放机制；处理长文本和小窗口裁切。
- 睡眠成功播放一次短音效；失败只显示原因。不要用循环背景音乐接口反复创建播放器。
- 优先复用既有音频对象；文件由 A 管理，E 提供用途和资源路径需求。
- 音乐关闭或音量为0时仍应能正常完成全部功能。

## 8 存档交接和加载顺序

D 负责 SaveManager 与格式。E 提供 gameMinutes、结算标记和恢复后刷新入口，B 提供农田结算字段。季节从日期推导，避免两份状态不一致。

加载顺序：停止调度 → D 读取并验证完整候选 → 恢复农田、库存、位置、时间与标记 → 校验跨域一致性 → 刷新日历/环境/HUD → 开启调度。

本轮不计算离线收益。应用关闭的现实时间不能直接加入游戏分钟。游戏运行中最小化的行为与关闭游戏不同，应按团队约定验证。

新档初始化应在第一次 updateTime/自动保存之前完成。读档失败不得由计时器自动覆盖原文件；不支持的旧档明确提示，由 D 管理处理流程。
